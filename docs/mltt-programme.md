# Characterising MLTT: programme

The current development is a fragment: a well-scoped indexed syntax, a
dependent case with constructor telescopes, uniform signatures for
`Nat`/`Vec`/`Fin`/`Eq`, and a positivity gate.  A complete characterisation of
MLTT needs more than more case rules.  It needs a single core with conversion,
metatheory, a model, and the transport theorem for the supercompiler.

This note fixes that spine and the order of work.

## 1. What “characterise” means

A characterisation of MLTT has four faces:

1. **Syntax and typing.**  A well-scoped core with contexts/telescopes and the
   type formers: universes, `Pi`, `Sigma`, identity, inductive families, and
   the eliminators.
2. **Definitional equality.**  A conversion relation with beta, eta, `J`, and
   case computation; typing up to conversion.
3. **Metatheory.**  Weakening, substitution, context morphisms, subject
   reduction, progress, strong normalisation, confluence, canonicity, and
   decidability of conversion/typing.
4. **Semantics.**  A category-with-families model, the term model, initiality,
   and the homotopy/∞-groupoid interpretation of identity; univalence and the
   Cubical model.

The supercompiler and its transport theorem sit on top: a type-preserving
translation of residual programs, justified by the object theory and its
model.

## 2. The core

The programme converges on one core, not the current split:

```text
Tm, Ctx, Env
  var, sort, pi, lam, app, sigma, pair, fst, snd,
  ind, roll, case, rec, refl, J
```

with:

- a **single telescope convention**: parameters, indices, constructor
  arguments, and result indices in the same de Bruijn order;
- well-scoped terms and well-formed signatures;
- conversion in the typing judgment;
- a recursor `rec` with induction hypotheses, not only `case`;
- the identity type as an inductive family or a primitive with `J`.

The current `HasType`/`HasTypeDep` split is transitional.  The target is one
`HasType` over the uniform convention; the old `Eq` proofs become validation
tests for the new core, not a parallel theory.

## 4. Metatheory targets

The order matters because each layer consumes the previous one.

1. **Telescope contexts.**  A context is a telescope; lookup, weakening, and
   substitution are telescope operations.  This replaces the positional
   `ctxExtendMany` workarounds.
2. **General weakening and substitution.**  For every term former, including
   `roll` and `case`; result indices substitute the full argument list.
3. **Conversion.**  A congruence generated by beta/eta, `J`, and case
   computation; conversion is stable under weakening and substitution.
4. **Subject reduction.**  Every step preserves typing; the branch context of a
   case/recursor is the constructor telescope, with induction hypotheses for
   the recursor.
5. **Progress and canonicity.**  For the total fragment, closed normal forms are
   canonical; the empty and unit families behave.
6. **Strong normalisation and confluence.**  The standard reducibility/
   logical-predicate route, or a normalisation-by-evaluation model for the
   fragment.  Confluence is needed for conversion decidability.
7. **Decidability.**  Conversion and typing for the fragment; a certificate
   checker for the supercompiler can rely on it.

## 5. Semantics

The semantic face is not decoration; it is what makes the transport theorem
meaningful.

- **CwF**: contexts, types, terms, comprehension, `Pi`, `Sigma`, identity,
  inductive families.
- **Term model**: the syntax forms the initial CwF with the type formers.
- **HoTT**: identity as a path object; the family fibration; transport along a
  path; univalence.  The Cubical Agda work (`cubical/Packing.agda`,
  `cubical/Coherence.agda`) is the current type-level experiment.
- **Obstruction**: univalence cannot be added over Lean’s proof-irrelevant
  `Eq`; the Cubical path equality is the separate regime.

A complete characterisation proves the term model is initial and the intended
HoTT model interprets the same core.  The current repository has neither the
CwF nor the initiality theorem.

## 6. Transport and supercompilation

The transport theorem is the correctness condition for a type-preserving
supercompiler:

```text
source program t : A
residual program sc(t) : A'
transport : A' -> A   (or a path/equivalence)
```

The programme needs:

1. a process graph for driving, generalisation, folding, and residualisation
   over the core;
2. a type translation for residual programs;
3. a logical relation or contextual equivalence between source and residual
   programs;
4. the transport theorem instantiated at the translation;
5. a first-order certificate checker for the fragment, with the dependent
   checker to follow.

The current first-order reverse certificate/derivation is the validation
case; the dependent instance is open.  The equivalence layer — definitional,
contextual, logical, bisimulation/Howe, and HoTT type equivalence — is fixed in
[docs/equivalence.md](equivalence.md).

## 8. Boundary of the current claims

- The old `HasType` has `Eq` `J`/weakening and beta on the function fragment;
  it has a nullary-only `case` and the parameter-only result-index convention.
- `HasTypeDep` has a dependent case and `rollDep`, but no own `pi`/`lam`/`app`
  rules; it depends on `ofHasType`.
- `WellFormedSigFull`/`Conventions.lean` start the uniform convention; four
  signatures and their gates are checked.
- No conversion, subject reduction, progress, SN, confluence, canonicity,
  decidability, CwF, initiality, or dependent supercompiler is claimed.
